# v1 演示脚本（Mock 模式，无需外部凭证）

> 适用：阶段一验收演示、答辩录屏。全程不访问飞书/GitHub/大模型，数据来自 Mock 采集器。

## 0. 前置

- Python 3.12+、uv 已安装
- 仓库根目录执行

```bash
export UV_CACHE_DIR=D:/uv-cache
uv sync --dev
```

## 1. 初始化与演示数据

```bash
export APP_SECRET_KEY=demo-secret
export MOCK_MODE=true

uv run python -m daily_report init-db
uv run python -m daily_report seed-demo
```

预期：`data/daily_report.db` 创建成功；写入成员张三（ou_1）、李四（ou_2）与团队「研发一组」。

## 2. 运行日报流水线

```bash
uv run python -m daily_report run --date 2026-11-11
```

预期输出（节选）：

```json
{
  "status": "success",
  "events": 4,
  "inserted": 4,
  "removed": 0,
  "degraded": false,
  "pushed": true
}
```

流水线内容：飞书日历 / 云文档 / 任务 + GitHub 各 1 条事件 → 归属 → 四段式草稿 → 推送记录。

再次执行同一命令，预期 `"status": "skipped"`（幂等，不重复生成或推送）。

## 3. 查看生成结果

```bash
uv run python - <<'PY'
import sqlite3, json
conn = sqlite3.connect("data/daily_report.db")
print("reports:", conn.execute("select id, member_id, report_date, status from report").fetchall())
print("items:", conn.execute("select section, content from report_item").fetchall())
print("pushes:", conn.execute("select channel, target_id, status from push_record").fetchall())
print("runs:", conn.execute("select run_key, status from pipeline_run").fetchall())
PY
```

## 4. 启动 API 并走确认流程

```bash
uv run python -m daily_report serve
```

另开终端：

```bash
curl -s localhost:8000/api/health
# {"status":"ok","mock_mode":true}

TOKEN=$(curl -s "localhost:8000/api/oauth/feishu/callback?code=ou_1" | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

curl -s -H "Authorization: Bearer $TOKEN" localhost:8000/api/reports/2026-11-11
curl -s -X POST -H "Authorization: Bearer $TOKEN" localhost:8000/api/reports/1/submit
curl -s -X POST -H "Authorization: Bearer $TOKEN" localhost:8000/api/reports/1/push
curl -s -H "Authorization: Bearer $TOKEN" "localhost:8000/api/teams/1/digest?report_date=2026-11-11"
```

预期：草稿 → `submitted` → `pushed`；汇总只包含已提交成员，且不含排名。

## 5. 真实凭证模式（可选）

将 `.env.example` 复制为 `.env`，填写飞书、GitHub、模型密钥，并设置 `MOCK_MODE=false`；命令不变，采集与推送切换到真实适配器，契约不变。

## 6. 演示要点

1. 采集 → 生成 → 推送全链路可运行，且重复执行幂等；
2. 每条日报条目带来源事件 ID，可追溯；
3. 单源失败隔离（移除某个采集器仍能产出日报）；
4. 模型失败降级为模板，不阻断提交；
5. 审计日志只记录元数据，不含正文与令牌。
