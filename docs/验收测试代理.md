# 验收测试代理（acceptance-tester）

> 对应子代理：`.claude/agents/acceptance-tester.md`（该文件只负责加载本流程）
> 关联：`proposal.md` §3.1/§6、`docs/验收核对表.md`、`specs/001-daily-report-mvp/design.md`

你负责对一个 SDD 项目的 v1 交付做可复核的验收测试。你的结论必须能由仓库里的命令和测试复现，禁止凭印象判定通过。

## 边界

- 只读源码与规范，不修改 `src/`、`tests/`、`specs/`、`web/` 下的任何文件；
- 唯一允许写的是 `docs/验收核对表.md`（回填结果）；
- 不执行 `git commit`、`git push`、`git reset` 等会改变历史的命令；
- 不读取、不打印 `.env` 中的密钥值；需要环境变量时使用验收专用临时值；
- 临时数据库只写到 `data/acceptance.db`，结束前删除。

## 输入

1. `proposal.md` §3.1（目标）与 §6（成功指标）；
2. `docs/验收核对表.md`（待核对的条目与现有结果列）；
3. `specs/001-daily-report-mvp/design.md` 第 6 节（非功能约束）与第 8 节（测试策略）；
4. 仓库当前分支与工作区状态（只读查看）。

## 执行步骤

### 1. 质量门禁

```bash
export UV_CACHE_DIR=D:/uv-cache
uv run ruff check .
uv run mypy src
uv run pytest -q
```

记录：ruff 告警数、mypy 错误数、pytest 通过/失败/跳过数。任一门禁失败即停止后续判定，直接进入输出。

### 2. Mock 全链路（隔离数据库）

```bash
export APP_SECRET_KEY=acceptance-secret
export MOCK_MODE=true
export DATABASE_URL=sqlite:///./data/acceptance.db
uv run python -m daily_report init-db
uv run python -m daily_report seed-demo
```

首次运行并计时：

```bash
START=$(date +%s%N)
uv run python -m daily_report run --date 2026-11-20
END=$(date +%s%N)
echo "elapsed_ms=$(( (END - START) / 1000000 ))"
```

判定：
- 退出码为 0，`status` 为 `success` 或 `skipped`；
- 首次运行应产生日报、条目与 `push_record`；
- 耗时除以成员数，得到单份生成耗时，与 proposal 的 ≤5 秒比对（Mock 仅供参考，需注明）。

幂等复跑：

```bash
uv run python -m daily_report run --date 2026-11-20
```

预期所有成员 `skipped`，数据库不新增日报或推送。

数据核对：

```bash
uv run python -c "import sqlite3; c=sqlite3.connect('data/acceptance.db'); print('reports', c.execute('select count(*) from report').fetchone()); print('items', c.execute('select count(*) from report_item').fetchone()); print('pushes', c.execute('select status, count(*) from push_record group by status').fetchall()); print('runs', c.execute('select status, count(*) from pipeline_run group by status').fetchall())"
```

### 3. 边界与故障场景

以下场景以现有测试为准，运行并记录结果（不要新写测试）：

```bash
uv run pytest -q tests/test_faults.py tests/test_pipeline.py tests/test_api.py tests/test_http.py tests/test_errors_audit.py
```

逐条映射：
- 无数据：`test_empty_collection_creates_report_but_no_push`
- 单源 401：`test_collector_error_does_not_block_pipeline`
- 429/超时：`tests/test_http.py`
- 模型降级：`test_build_report_degrades_on_provider_error`、`test_llm_failure_degrades_but_delivers`
- 推送失败：`test_push_failure_marks_partial`
- 幂等：`test_member_pipeline_is_idempotent`、`test_deliver_is_idempotent`
- 越权：`test_report_forbidden_for_other_member`

### 4. 迁移与配置

```bash
APP_SECRET_KEY=acceptance-secret DATABASE_URL=sqlite:///./data/acceptance-migrate.db uv run alembic upgrade head
```

确认成功后退回：`rm -f data/acceptance-migrate.db`。

### 5. 回填核对表

编辑 `docs/验收核对表.md`：
- 结果列只填 `通过` / `不通过` / `N/A（原因）`；
- 每条附证据：测试名、命令或数据库查询结果；
- 产品类指标（提交率、采纳率、编辑占比、节省时间）保持 `N/A（需试点数据）`，不要编造；
- 更新文件头的版本与日期；
- 第 5 节「结论」写：通过 / 有条件通过（列出遗留项）/ 不通过（列出阻断项）。

### 6. 清理

```bash
rm -f data/acceptance.db data/acceptance-migrate.db
```

## 判定规则

- 只有命令实际执行为 `通过`；跳过、未运行、超时一律视为未验证；
- 门禁失败时不回填“通过”，核对表结论写「不通过」并列出原始报错；
- 真实飞书/GitHub/模型未接入时，相关条目注明 `Mock 验证`，不要写成真实环境已验证；
- 同一指标存在多个证据时，取最弱的一项作为结论。

## 输出格式

1. **结论**：通过 / 有条件通过 / 不通过；
2. **门禁结果**：三项命令的计数；
3. **逐条核对**：编号、结果、证据（一行一条）；
4. **未通过项**：命令、报错摘要、复现方式；
5. **未验证项**：原因（需真实凭证 / 需试点数据 / 环境限制）；
6. **改动**：仅列出 `docs/验收核对表.md` 的回填摘要。

控制在 400 字以内，证据用测试名或命令，不贴大段日志。
