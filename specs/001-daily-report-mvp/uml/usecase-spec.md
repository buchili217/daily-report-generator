## 3. 关键用例详述

### UC-01 飞书登录与授权

| 项目 | 内容 |
|---|---|
| 参与者 | 主要：一线员工；次要：飞书开放平台 |
| 触发事件 | 员工首次打开应用或令牌过期 |
| 前置条件 | 企业已安装自建应用，回调地址已登记 |
| 后置条件 | 建立会话，保存加密后的用户令牌与授权范围 |
| 主成功场景 | 1. 员工点击登录，系统跳转飞书 OAuth 授权页<br>2. 飞书回调携带 `code`<br>3. 系统用 `code` 换取 `user_access_token` 与用户信息<br>4. 创建/更新 `member`，签发 JWT 会话<br>5. 跳转日报首页 |
| 备选场景 | 3a. 用户拒绝授权 → 返回首页并提示所需权限及用途 |
| 异常场景 | 飞书返回 401/403 → `E-COL-001`，提示重新授权，不创建会话 |
| 关联需求 | proposal §5 登录授权；澄清 Q-14 |
| 验收标准 | 授权后能读取本人日历列表；令牌不出现在日志与响应体中 |

### UC-04 确认并提交日报

| 项目 | 内容 |
|---|---|
| 参与者 | 主要：一线员工 |
| 触发事件 | 员工在草稿页点击「提交」 |
| 前置条件 | 存在当天 `draft` 状态日报；员工为本人 |
| 后置条件 | `report.status=submitted`，写入 `report_version`，记录审计日志 |
| 主成功场景 | 1. 系统校验日报归属与状态<br>2. 校验条目均带来源或为手填<br>3. 状态改为 `submitted`，记录 `submitted_at`<br>4. 生成版本快照<br>5. 返回提交成功与摘要 |
| 备选场景 | 2a. 存在未确认的低置信度条目 → 提示勾选或删除后才能提交 |
| 异常场景 | 非本人操作 → 403 拒绝；重复提交 → 幂等返回已提交结果 |
| 关联需求 | proposal §5 编辑确认；澄清 Q-07 |
| 验收标准 | 提交后 `report_item.source_event_ids` 非空或标记为手填；重复提交不产生新版本 |

### UC-08 采集工作数据

| 项目 | 内容 |
|---|---|
| 参与者 | 主要：定时调度 |
| 触发事件 | Celery Beat 每工作日 17:30 触发 |
| 前置条件 | 成员凭证有效；采集源已启用 |
| 后置条件 | `work_event` 新增/更新；`sync_cursor` 前移 |
| 主成功场景 | 1. 读取成员与已启用数据源<br>2. 并行调用 UC-09～UC-12（并发 ≤3）<br>3. 结果按 `(source, source_id)` 去重入库<br>4. 更新游标与 ETag<br>5. 汇总各源成功/失败数量 |
| 备选场景 | 2a. 某源未授权 → 跳过该源并记录 `E-COL-001`，继续其它源 |
| 异常场景 | 429 → `E-COL-002`，按 `Retry-After` 退避后重试（≤3 次）；超时 → `E-COL-003`，记录后继续 |
| 关联需求 | proposal §5 采集；澄清 Q-01 |
| 验收标准 | 同一时间窗重复执行，`work_event` 行数不增加；单源失败不影响其它源入库 |

### UC-13 生成日报草稿

| 项目 | 内容 |
|---|---|
| 参与者 | 主要：定时调度；次要：LLMProvider |
| 触发事件 | 采集完成后由流水线调用 |
| 前置条件 | 当天存在可归属的 `work_event`，或允许生成空模板 |
| 后置条件 | 生成 `draft` 日报与四段式条目 |
| 主成功场景 | 1. 聚合去重、时间窗过滤（UC-08 结果）<br>2. 计算归属与置信度（UC-14）<br>3. 按模板组织四段式结构<br>4. 调用模型生成自然语言<br>5. Schema 与来源校验（UC-15）<br>6. 保存草稿与版本 |
| 备选场景 | 3a. 无任何事件 → 生成空白模板并提示「今日无可采集数据」 |
| 异常场景 | 模型超时/限流/非法 JSON → `E-GEN-001/003`，重试后降级为事实模板；无来源条目 → `E-GEN-002`，剔除 |
| 关联需求 | proposal §5 AI 生成；澄清 Q-07 |
| 验收标准 | 任一条目均可在 `source_event_ids` 中找到来源；模型不可用时仍能产出可提交草稿 |

### UC-16 推送日报

| 项目 | 内容 |
|---|---|
| 参与者 | 主要：定时调度 / 一线员工；次要：飞书开放平台 |
| 触发事件 | 日报提交后自动推送，或员工手动点击「推送到飞书」 |
| 前置条件 | `report.status=submitted`；目标会话有效 |
| 后置条件 | `push_record.status=sent`，记录 `provider_msg_id` |
| 主成功场景 | 1. 校验日报状态与推送目标<br>2. 生成幂等键（report_id + 渠道 + 目标）<br>3. 发送飞书卡片<br>4. 写入推送记录与审计日志 |
| 备选场景 | 2a. 已存在成功记录 → 直接返回，不重复发送 |
| 异常场景 | 凭证失效 → `E-PUSH-001`，提示重新授权，不重试；目标不存在 → `E-PUSH-002`；网络超时 → 指数退避重试（≤3 次） |
| 关联需求 | proposal §5 推送 |
| 验收标准 | 同一日报重复推送同一目标，飞书侧只收到一条消息 |

### UC-17 查看团队日报汇总

| 项目 | 内容 |
|---|---|
| 参与者 | 主要：团队负责人 |
| 触发事件 | 负责人打开团队汇总页或收到汇总卡片 |
| 前置条件 | 负责人与团队成员关系已配置；成员日报已提交 |
| 后置条件 | 展示按人分组的完成/进行中/风险与阻塞，不展示排名 |
| 主成功场景 | 1. 校验负责人权限（仅直属团队）<br>2. 查询指定日期 `submitted/pushed` 日报<br>3. 聚合阻塞项与跨人依赖<br>4. 返回汇总视图 |
| 备选场景 | 2a. 部分成员未提交 → 在汇总中标记「未提交」，不阻断展示 |
| 异常场景 | 越权访问非直属团队 → 403；无数据 → 返回空视图并提示 |
| 关联需求 | proposal §5 团队汇总；澄清 Q-10 |
| 验收标准 | 负责人只能看到直属成员；汇总中不出现个人排名或绩效评分 |
