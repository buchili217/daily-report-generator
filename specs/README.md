# 规格目录（Specs）

本目录存放 SDD（规格驱动开发）流程中的需求与设计文档。**先写规格，再写代码**。

## 目录约定

```
specs/
├── README.md
├── 000-template/          # 模板，不直接修改
│   ├── spec.md
│   ├── plan.md
│   └── tasks.md
└── NNN-<slug>/            # 每个功能一个目录
    ├── spec.md            # 做什么、验收标准
    ├── plan.md            # 怎么做、数据模型、接口
    └── tasks.md           # 任务拆解与状态
```

- `NNN`：三位递增编号，从 `001` 开始；
- `<slug>`：英文小写、中划线分隔，例如 `001-feishu-calendar-sync`；
- 一个目录对应一次功能迭代，跨多个 PR 时共用同一目录。

## 文件职责

| 文件 | 回答的问题 | 评审要求 |
|---|---|---|
| `spec.md` | 做什么？为什么做？怎么算完成？ | 必须评审通过才能进入设计 |
| `plan.md` | 怎么做？涉及哪些模块、表、接口？ | 技术负责人评审 |
| `tasks.md` | 拆成哪些可执行任务？谁做？ | 开发前拆完 |

## 工作流

1. 复制 `000-template/` 为 `NNN-<slug>/`；
2. 填写 `spec.md`，明确用户故事与验收标准（Given/When/Then）；
3. 评审通过后填写 `plan.md`；
4. 拆解 `tasks.md`，标注依赖与状态；
5. 开发时每个 PR 引用对应任务编号；
6. 功能完成后在目录下补充 `notes.md`（可选，记录决策与遗留问题）。

## 状态标记

`tasks.md` 中使用：

- `TODO`：未开始
- `DOING`：进行中
- `DONE`：已完成
- `BLOCKED`：被阻塞（注明原因）
